# 0002. Use CEL as the single expression language

* Status: accepted (library: `cel` 0.15.0)
* Date: 2026-11-04
* Deciders: Mustafa

## Context

Macros need predicates (`when`, `until`, `if`), guards, goals and updaters. Four layers needed one language: predicates, node selectors, data-flow refs, driver queries.

Library: Rust crate `cel` 0.15.0 (cel-rust org), pinned exactly. It has parser limits (`max_recursion_depth`, `max_expression_node_count`) but no runtime cost or time limit, so cap expression size at load and evaluate under a timeout. Licenses still to check.

## Options considered

1. CEL: typed, non-Turing-complete, type-checkable at load.
2. Starlark: rejected (needs a scripting ADR, too powerful).
3. OPA/Rego: parked (Regorus is the Rust engine option).
4. JMESPath, JSONPath, JSONLogic: rejected (gaps, extra language).

## Decision

Use CEL, profile `handsfree-cel/1`, for guards, `until`, `when`, goals, updaters.

Rules:

* Variables: `params`, `ops.<id>.out`, `obs`, `run`, `state`, `now`.
* Fill gaps with host functions, not a new language: `stable_for(expr, ms)`, `changed(expr)`, `prev`, `coalesce(a, b)`.
* Type-check at macro load. Guard error = false (fail closed).
* Evaluate on a snapshot. Never call a driver mid-evaluation. Keeps replay deterministic.
* Separate scopes: owner policy file vs model-written macro.

## Consequences

* Good: one language, shared conformance fixtures across engines.
* Bad: CEL gotchas (missing field = error, `&&`/`||` absorb errors) need tests.
* Follow-ups: define variables, functions and limits of `handsfree-cel/1`. Spike evaluation time on a large node list (the library has no cost limit).

## Verification

Property tests as conformance across engines. Spike results recorded here.
